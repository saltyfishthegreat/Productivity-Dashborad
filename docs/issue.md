# Issue 1：实现任务完整 CRUD
## 目的

将当前使用 Mock 数据渲染的任务模块升级为可以真实操作的任务管理功能。

## 功能范围

- 创建任务
- 编辑任务
- 切换任务完成状态
- 删除任务
- 更新任务列表状态

## 验收标准

- [ ] 用户可以通过 Add Task 表单创建任务
- [ ] 新任务提交后立即显示在任务列表中
- [ ] 用户可以编辑任务标题、优先级和状态
- [ ] 用户可以切换任务的完成状态
- [ ] 用户可以删除任务
- [ ] 操作一条任务不会影响其他任务
- [ ] 创建、编辑和取消状态不会互相冲突
- [ ] 继续使用现有 Task、Status 和 Priority 类型
- [ ] 没有新增明显的 TypeScript `any`
- [ ] 项目可以正常运行和构建

## 不在本 Issue 范围

- localStorage 持久化
- 任务搜索和筛选
- 数据库
- Redux 或 Zustand
- 拖拽排序

## 可见产出

- 一个完成任务 CRUD 的 commit 或 PR
- 一张任务创建和状态切换截图

## 建议分支

`feat/task-crud`
建议标签： feature、week-2、priority-high
Issue 2：添加任务表单校验与 localStorage 持久化
## 目的

保证任务表单的错误路径可预测，并让任务数据在页面刷新后继续存在。

## 功能范围

- 任务标题必填校验
- 表单错误提示
- localStorage 写入
- 页面加载时恢复任务
- localStorage 异常数据处理

## 验收标准

- [ ] 空任务标题不能提交
- [ ] 标题为空时显示明确的错误提示
- [ ] 合法提交后清空表单和错误状态
- [ ] 取消编辑不会修改原任务
- [ ] 创建、编辑、完成和删除任务后自动更新 localStorage
- [ ] 刷新页面后任务数据仍然存在
- [ ] localStorage 没有数据时页面正常加载
- [ ] localStorage 数据格式错误时页面不会崩溃
- [ ] 服务端渲染阶段不直接访问 `window` 或 localStorage
- [ ] localStorage 操作没有散落在多个 UI 组件中

## 不在本 Issue 范围

- 云端同步
- 数据库
- 用户登录
- 跨设备同步

## 可见产出

- 刷新前后任务仍然存在的截图或短录屏
- 一个持久化功能 commit 或 PR

## 建议分支

`feat/task-persistence-validation`
建议标签： feature、validation、week-2、priority-high
依赖： Issue 1

# Issue 4：为 CRUD 核心行为添加自动化测试

## 目的

通过少量高价值测试验证任务和笔记的核心用户行为，防止重构破坏主要功能。

## 最低测试范围

- 创建任务
- 任务表单校验
- 笔记创建、编辑或删除
- localStorage 数据恢复

## 验收标准

- [ ] 输入合法标题后可以创建任务
- [ ] 空任务标题不能创建任务
- [ ] 点击完成按钮后任务状态正确变化

- [ ] 如果持久化逻辑容易隔离，覆盖 localStorage 数据恢复
- [ ] 测试使用现有项目的测试工具
- [ ] 测试关注用户可见行为，不依赖组件内部实现
- [ ] 所有新增测试通过

## 建议分支
